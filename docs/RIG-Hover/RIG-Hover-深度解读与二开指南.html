1. 它是什么？用大白话说

RIG-Hover（中文昵称「文文」）是陆吾智能 RIG 系列里的双轮自平衡桌宠： 极窄轮距、低重心、头部能左右张望，能听懂「小陆同学」、能聊天、能表情、能动起来。

真正有意思的是：它的「大脑」固件叫 rig_omni—— 同一套代码还能编译出机器狗（Puppy）和机械臂（Arm）。 你买到的 Hover，只是编译时勾选了 BOARD_TYPE_HOVER 的那一版。

硬件一句话

ESP32-S3 + 双 FOC 轮电机 + 1 个头部舵机 + IMU + 圆屏 + 麦克风/喇叭 + GC0308 摄像头

软件一句话

本地唤醒 → 云端 ASR/LLM/TTS → MCP 工具控制头/轮 → LQR 每几毫秒维持不倒

开源价值

不是玩具黑盒：板级、协议、平衡、MCP、摄像头链路全部可读可改，Apache 2.0

规格数值
尺寸 / 重量约 61×61×139 mm · ~375g
自由度3（双轮差速 + 头部水平 ±70°）
最高滑行速度~10 cm/s
电池2S 7.4V · 500mAh · Type-C
续航自平衡待机 ≥1.5h · 互动 ≥1h
控制周期~1–6 ms 级（LQR 平衡环）
上手提醒：上电时务必手扶竖直 2–3 秒，等 IMU 校准完成、感到轮部有轻微「对抗」后再松手。 配网后设备会重启并暂时失衡——请扶住，避免摔坏。

2. 通电之后发生了什么？

把整机想象成「五条并行的流水线」：

  1. 站稳：IMU 读姿态 → LQR 算力矩 → UART 发给左右轮（一直在跑，和聊天无关）
  2. 听声：麦克风 → 本地唤醒词「小陆同学」→ 开始录音
  3. 上网说话：Opus 音频上行 → 云端 ASR → LLM → TTS → 喇叭播放
  4. 做事：LLM 通过 MCP 调用工具（转头、前进、拍照……）
  5. 表情：圆屏用 EAF 动画播 happy / listen / thinking 等
开机 → NVS / WiFi 配网（BluFi 或 AP） → 访问 OTA 接口（拿 mqtt/websocket 配置 + 检查固件） → 选协议（MQTT 或 WebSocket） → 空闲待机（Idle）+ 唤醒词监听 → 唤醒 → Connecting → Listening → Speaking → Idle （全程 xgo_control / imu / 音频任务并行）

设备状态机（简化）

固件用 12 种状态管理生命周期，日常对话主要在这四个之间转： Idle ⇄ Connecting → Listening → Speaking。 另有配网、OTA 升级、激活、致命错误等状态。

4. 云端对话是怎么连上的？

设备不自带写死的聊天服务器地址。开机联网后，它先请求一个 OTA 配置接口：

  • 国内默认：https://xl-api.xgorobot.com/xiaolu/ota/
  • 海外默认：https://xl-api.luwudynamics.ai/xiaolu/ota/
  • 可用 NVS 键 wifi/ota_url 覆盖

该接口返回的 JSON 里，若带 mqtt{...} 或 websocket{...}， 固件会把参数写入 NVS，并据此选择协议。 没有配置时默认走 MQTT。

两条通道对比

项目WebSocketMQTT
控制/JSON同一条 WSMQTT Topic
音频同一条 WS（Opus）独立 UDP + AES-CTR 加密
NVS 配置url / token / versionendpoint / client_id / username / password / publish_topic

一次对话里的关键消息

方向type含义
设备→云hello握手：声明 opus / mcp / aec
设备→云listen开始/停止听；唤醒时带唤醒词文本
云→设备stt用户说了什么（字幕）
云→设备tts开始/停止播放；逐句字幕
云→设备llm切换表情 emotion
双向mcpJSONRPC 2.0：AI 调工具 / 工具回结果

MCP：让 AI「动手」

设备是 MCP Server，云端 LLM 是 Client。 AI 发现工具列表后，可以调用例如：

  • self.robot.head_angle — 转头
  • self.robot.move — 前进/后退（厘米）
  • self.robot.rotate — 原地转向
  • self.camera.take_photo — 拍照并识图
  • self.camera.preview — 拍照上屏
  • 以及音量、亮度、电量、语言等通用工具
官方桌面站： agent.xgorobot.com 可配置智能体、知识库、声音复刻、MCP。 微信小程序「小陆同学」功能对齐。

5. 为什么它不会倒？——LQR 平衡控制

Hover 的「站稳」不依赖聊天云，是本地实时控制。 三个 FreeRTOS 任务：

  • xgo_task → 循环调用 xgo_control()
  • xgo_rx_task → 读电机/舵机反馈
  • imu_task → 读 QMI8658C 的 roll/pitch/yaw

控制思想（通俗版）

每几毫秒看一眼：位置偏了多少、速度偏了多少、身子倾了多少、倾的有多快， 用四个增益加权合成一个力矩，再拆成左右轮差速。这就是离散 LQR： 

u = -( K0·位置误差 + K1·速度误差 + K2·俯仰误差 + K3·俯仰角速度 )
默认：lqr_k = {1400, 6.8, 32, 1.6}
航向：yaw_u = k_yaw · (yaw - 头角 - 目标航向)
输出：左轮 = -u + yaw_u，右轮 = +u + yaw_u

安全保护（二开必须保留）

  • 俯仰 ≥60° 或横滚 ≥40° 持续 0.5s → 切断力矩
  • 直立 <7° 持续 1.5s → 重新允许平衡
  • 轮速异常偏大 → 判定被拿起，切断力矩

局域网调参

WiFi 连上后访问 http://<设备IP>/， 可实时看 IMU，并热调 head / delta_pos / imu_zero / LQR_k0~k3 等。

调参顺序建议： imu_zero → LQR_k2 → LQR_k3 → LQR_k1 → LQR_k0 → k_yaw。 每次小幅改；先悬空测电机方向，再手扶，最后放地。 不要一开始就猛加 LQR_k0（容易来回冲击）。

6. 拍照与多模态：已经内置了

Hover 板上的 GC0308 摄像头已接入。AI 说「看看这是什么」时，会调用 self.camera.take_photo：

  1. 本地抓取 240×240 RGB565 帧
  2. 软编码 JPEG
  3. 以 multipart/form-data（字段 question + file）POST 到识图 URL
  4. 把服务器返回的文字分析结果带回对话

识图 URL 不是写死在固件里的：来自 MCP initialize 握手时 服务端下发的 capabilities.vision.{url, token}。

二开含义：你自建后端时，只要在 MCP initialize 里带上自己的 VLM 接口地址， 并实现「接收 JPEG + question → 返回文字」即可接上多模态。 仅拍照上屏用不带分析的 self.camera.preview。

7. 二次开发：怎么下手？

第 1 天

跑通工程

按上面编译烧录；串口能看到 Hover 日志、屏能播表情、按键能进配网/切聊天。

第 2 天

读板级初始化

顺着 hover_board.cc 看 SPI/LCD/按键/摄像头/UART/控制器初始化顺序。

第 3 天

串口电机协议

只测头部 ID3；再读轮反馈；小力矩确认左右方向一致。

第 4 天

理解平衡

Web 调参页观察 pitch；小幅改 imu_zero 与 LQR_k2/k3。

第 5 天

加一个动作

在 InitializeTools() 注册新 MCP 工具；回调里只改目标量（stable_pos / stable_yaw / target_head_pos），不要阻塞。

常见改动放哪里

你想做的事改哪里
新增动作 / MCP 工具hover_board.cc 的 InitializeTools()
改引脚只改 boards/hover/board_config.h
新表情boards/hover/emoji/*.eaf + 240_240/emote.json

8. 连接自己的服务器 / AI Agent：三条路

这是深度二开里最关键的一块。按「改动量从小到大」排列：

路径 A

继续用官方固件，只换「大脑配置」

在 agent.xgorobot.com 或小程序里改智能体提示词、知识库、音色。 适合：先玩通产品，不碰固件。 局限：流量仍走陆吾云，不能完全自托管。

路径 B

自建「兼容小智/小陆」协议的后端（改 OTA 指向）

核心：让设备的 OTA URL 指向你的服务器，返回合法的 websocket 或 mqtt 配置。 之后实现 hello / listen / stt / tts / llm / mcp 消息流 + Opus 音频。 视觉：在 MCP initialize 里下发 capabilities.vision.url。 适合：想完全掌控对话与工具编排，且愿意实现协议服务端。

路径 C ★推荐入门自托管

换用官方 BYOK 分支：rig_local

rig_local 是 rig_omni 的「无服务器版」：删掉 MQTT/WebSocket 云协议， 换成 cloud_api 模块，设备直连厂商 API（Bring Your Own Key）。 Hover / Puppy / Arm 板级代码仍保留——换脑不换身。

路径 C 详解：rig_local 能干什么

能力绑定情况能否指到自己的服务
LLM任意 OpenAI 兼容接口✅ 可指向 OpenAI / DeepSeek / 火山 / 自建 vLLM·Ollama
VLM（识图）OpenAI 兼容视觉模型✅ 同上，自定义 base_url / model / key
ASRDashScope Qwen 实时 ASR⚠️ 专有 WebSocket；完全自托管需改 asr_client
TTSDashScope Qwen TTS⚠️ 同上；完全自托管需改 tts_client

配置方式（优先级从高到低）：

  1. 设备联网后打开 http://<设备IP>/ 网页填 Key（写入 NVS）
  2. idf.py menuconfig → Cloud API Direct Mode 编译默认值
  3. 用 rig_local_web / 在线站 rig-local.xgorobot.com 一键烧录：固件 + WiFi + API Key 一起写入
对你目标的映射： 「定制固件烧录 + 连自己服务器 + 自己的 AI Agent + 拍照多模态」→ 优先试 路径 C（rig_local） 把 LLM/VLM 指到自有 OpenAI 兼容服务； 若还需自建 ASR/TTS，再在 cloud_api 层替换客户端，或走路径 B 实现完整协议服务端。

路径 B：OTA 响应最小骨架（示意）

{
  "websocket": {
    "url": "wss://your.server/ws",
    "token": "your-token",
    "version": 3
  },
  "server_time": { "timestamp": 1735689600000, "timezone_offset": 480 },
  "firmware": { "version": "3.7.0", "url": "" }
}

设备还会 POST 自身 GetSystemInfoJson()（含 MAC、UUID、板型等）。 激活场景可能涉及 HMAC；开源复刻板通常按 Activation-Version 分支处理。

10. 建议你按这个顺序动手

  1. 先当用户玩通一遍
    手扶上电 → BluFi/小程序配网 → 唤醒「小陆同学」→ 试转头/前进/拍照。 确认硬件与官方云都正常。
  2. 本地编译官方 Hover 固件
    用本仓库 CONFIG_BOARD_TYPE_HOVER 烧录； 打开 http://设备IP/ 调一次 LQR，建立「改代码→烧录→验证」手感。
  3. 加一个自己的 MCP 动作
    例如「点头两下」：在 InitializeTools() 注册工具，只改 target_head_pos。
  4. 决定云策略
    要完全自托管 → 评估 rig_local（LLM/VLM 指自己的服务）； 要兼容现有小智协议生态 → 自建 OTA + WS/MQTT 服务端。
  5. 接多模态
    在自有后端实现 vision HTTP 接口，或在 rig_local 里配置 VLM base_url； 用语音说「看看桌上是什么」验证闭环。
  6. （可选）外挂电脑能力
    参考 mcp-demo-browser，把计算器/打开网页等工具挂到 MCP endpoint， 让桌宠指挥你的电脑。
一句话收束： RIG-Hover = 本地硬核平衡机 + 可扩展 MCP 工具箱 + 可替换的云端大脑。 深度二开时，运动与表情改 boards/hover/； 大脑与多模态改「OTA 协议服务端」或直接切到 rig_local。
